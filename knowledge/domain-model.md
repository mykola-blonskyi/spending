# Domain Model

All IDs are UUIDs. Entities that sync offline (transactions) receive their ID from the client;
every other ID is generated by the server. Money is always `amountMinor` (a safe integer of minor
units, e.g. cents) plus an ISO 4217 `currency`. Floating point never represents money.

## User

The local profile of an OIDC subject.

- `id`, `oidcSub` (unique), `email`, `displayName`, `avatarUrl`
- Preferences: `locale` (`en|uk|ru|es`), `theme` (`light|dark|system`), `timezone` (IANA)
- Base currency is always EUR (ADR-007), so it is not a column.
- Every user owns exactly one personal workspace, created on first sign-in.

## Session

An opaque, revocable server-side login session.

- `tokenHash` (SHA-256 of the cookie value, primary key), `userId`, `csrfToken`
- `previousTokenHash`: the hash before the last rotation, accepted for a short grace window so
  concurrent requests never fork the session
- `expiresAt`, `rotatedAt`, `lastSeenAt`
- `refreshTokenEnc` (the OIDC refresh token, AES-256-GCM encrypted) and `grantCheckedAt`. The API
  re-checks the provider grant by refreshing at most every 5 minutes (ADR-003).
- `idTokenEnc` (the OIDC ID token, encrypted the same way), sent as the logout hint to the
  provider's end-session endpoint.

## LoginAttempt

A pending OIDC authorization: `state` (primary key), `nonce`, `codeVerifier`, `returnTo`,
`expiresAt`. Single use. Deleted on callback or expiry. An `/invite/<token>` return target is
stored as `/invite`, so an abandoned login never keeps an invitation token (BR-8).

## Workspace

The ownership boundary for all ledger data.

- `kind`: `personal` (exactly one member, its owner) or `family`.
- `name` (null for a personal workspace, which the UI names in the user's language), `ownerId`,
  `createdAt`.
- A transaction's scope (personal or family) is the kind of its workspace. Scope is never a
  separate field that could disagree with the workspace.

## Membership

`(workspaceId, userId)`, `role` (`owner|member`), `joinedAt`. A user has at most one family
membership (ADR-008).

## Invitation

A one-time link into one family workspace.

- `id`, `workspaceId`, `tokenHash` (the link carries the raw token), `createdBy`
- `expiresAt`, and `state` derived from `acceptedAt`, `acceptedBy` and `revokedAt`:
  `pending | accepted | revoked | expired`.

## WorkspaceEvent

The family audit log, readable by members (newest 50).

- `id`, `workspaceId` (deleted with the workspace), `actorId` and `subjectUserId` (both nullable
  after account deletion), `createdAt`
- `type`: `family_created | renamed | invitation_created | invitation_revoked | member_joined |
member_left | member_removed | ownership_transferred`

## Account

Where money sits: a card, a bank account, cash.

- `id`, `workspaceId`, `name`, `currency`, `kind` (`cash|bank|card|savings|other`), `archivedAt`.
- Names are unique per `(workspaceId, kind)`, like categories. Accounts and categories are archived,
  never deleted.

## Category

- `id`, `workspaceId`, `name` (nullable), `kind` (`income|expense`), `color`, `icon`, `archivedAt`.
- `systemKey` (nullable, unique per workspace). Default categories carry a stable key such as
  `groceries` and no stored
  name: the web shows `name ?? t(categoryDefaults.<systemKey>)` from one module
  (`features/ledger/category-view.ts`). Renaming stores the user's name and keeps the key, which
  the import categorizer relies on; clearing the name returns to the default (BR-4a, ADR-012). Every new workspace, personal or family, is
  seeded with 14 expense and 6 income defaults (`workspaces/default-categories.ts`).

## Transaction

- `id` (client-generated), `workspaceId`, `createdBy` (nullable after the author deletes their
  account), `kind` (`income|expense`), `amountMinor` (> 0), `currency`, `occurredOn` (a date, no time)
- `accountId` (nullable), `categoryId` (nullable), `description`, `note`
- Conversion: `baseAmountMinor` (EUR, nullable when no rate exists), `fxRate` (decimal string),
  `fxRateDate`, `fxSource`
- `source` (`manual|import|recurring`), `importBatchId`, `importHash`, `externalId`
- `recurringRuleId` and `recurringOccurrence` (a date), unique together
- `reviewStatus` (`confirmed|pending_review`)
- `transferId` (nullable, shared by both sides of a transfer) and `transferOutside` (the other
  side is an own account outside the app). A transfer has no category (BR-37).
- `version` (incremented on user-visible changes only, so a background FX fill never causes a
  conflict), `revision` (global change sequence used as the sync cursor), `deletedAt` (a tombstone, so sync can propagate deletes), `createdAt`, `updatedAt`

## SyncMutation

The idempotency log for offline writes: `id` (client mutation UUID, primary key), `userId`,
`result` (JSON), `createdAt`. Replaying a mutation ID returns the stored result.

## SyncTombstone

Records that a transaction left a workspace (its author moved it), so that workspace's members
pull a tombstone for it: `(workspaceId, transactionId)` primary key, `revision` (from the global
change sequence, assigned at the move), `deletedAt`. A repeated move refreshes the row. Later edits
of the transaction never touch it (BR-2).

## SyncConflict

Created when an offline edit was based on a stale version.

- `id`, `transactionId`, `userId` (who must resolve it), `baseVersion`, `serverVersion`
- `local` (the client's intended write as JSON, or `{ deleted: true }`). The server side is always
  the live row, read when the conflict is shown.
- `status` (`open|resolved`), `resolution` (`server|local|merged`), `createdAt`, `resolvedAt`

## FxRate

`(date, currency)` holding `ratePerEur` (decimal string, units of the currency per 1 EUR) and
`source` (`ecb`).

## Budget

A monthly spending limit: `id`, `workspaceId`, `categoryId` (an expense category of the same
workspace), `amountMinor` (EUR), unique per `(workspaceId, categoryId)`.

## RecurringRule

- `id`, `workspaceId`, `createdBy`, the transaction template (kind, amount, currency, account,
  category, description)
- Schedule: `frequency` (`daily|weekly|monthly|yearly`), `interval` (>= 1), `startsOn`, `endsOn`
  (nullable), `timezone`
- `nextOccurrence` (the earliest occurrence not yet generated), `pausedAt`

## ImportBatch

- `id`, `workspaceId` (always the importer's personal workspace), `userId`, `accountId`
- `fileName`, `mapping` (JSON), `rowCount`, `importedCount`, `duplicateCount`, `rejectedCount`
- `rejected` (`{ line, reason }` per rejected row: `INVALID_DATE`, `INVALID_AMOUNT`,
  `INVALID_CURRENCY`, `CURRENCY_MISMATCH`, `DESCRIPTION_TOO_LONG`, `EXTERNAL_ID_TOO_LONG`,
  `DUPLICATE_IN_FILE_EXTERNAL_ID`), `createdAt`, `undoneAt`

## CategoryRule

What the categorizer learns: `(workspaceId, merchantKey)` maps to `categoryId`. It is written when
a user confirms or changes the category of an imported transaction.
